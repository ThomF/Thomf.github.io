Shipyard

            
Point it at a repo. It plans, builds, tests, fixes and ships.

            

              Shipyard pilots a feature through your codebase on its own. It plugs into a coding
              agent like Claude Code with custom commands that guide developer and tester agents
              as they build your feature, test it, and fix any issues. When the feature is ready,
              it can even ship it to your repo.
            

            

              The terminal below replays a real Frisson run, condensed. "Run again" moves on to three made-up examples.
            

            
            

              

                ~/frisson
                
              

              
> /shipyard "add an admin panel"
[plan]  3 tasks · 12 criteria
[build] dev agent → admin API ✓
[build] dev agent → dev admin login ✓
[build] dev agent → /admin panel ✓
[test]  tester agent → 828 tests ✓
[test]  browser agent → 99 steps ✓
[test]  12 of 12 criteria ✓
[ship]  branch shipped ↗
[pilot] /harbor → 19-step guide ✓

            

            

              What's the Harbor Pilot?
              

                
After a build, /harbor lays the real code out in the order the data moves, so a person can read it from start to finish.

                
It is not a reviewer: it does not approve, fix or score anything. You are the reviewer.

                
The code can't be paraphrased, because Claude only cites line ranges. A script copies those lines from the commit and refuses citations that don't exist.

                
/harbor ask answers with quoted lines. /harbor verify re-checks every snippet against the branch.
