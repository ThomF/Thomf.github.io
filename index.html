    • Clinical meeting tracker. An agency leader asked us to replace the Excel sheets their teams used to prep patient review meetings. Prep took hours, so most leaders skipped these meetings. We built a 10-step guided meeting that pulls patient data in automatically. I owned the prep page, about half the patient data pages, and the follow-up and resolve system for meetings of about 60 clinicians. After launch, teams told us notes were getting lost when meetings ran long, so I built carry-forward: any unresolved follow-up shows up in the next meeting. When an upstream data change caused one patient to get duplicate opt-in texts, I shipped a one-text-per-number guard right away, then fixed the root cause in the data.

    • Reliable multi-table saves. Forms that wrote to several tables were chained from Retool, so a refresh mid-save could leave half-written records. I moved each flow into a single Snowflake stored procedure that creates, updates or deletes from one payload, rolls back on failure and returns the new ID.

    • HL7 admit, discharge and transfer alerts. Care teams could only clear alerts all at once. I rebuilt about 50 alerts a week from flat event rows into per-patient timelines by location, with diagnoses, so teams could clear them location by location. Shipped in a few days.

Rebuilt my Retool risk prediction drawer, which shows a patient's likelihood of events like hospitalization, by directing Claude Code agents in small, reviewed steps to a pixel-perfect match with the design. Shipyard

            
Point it at a repo. It plans, builds, tests, fixes and ships.

            

              Shipyard pilots a feature through your codebase on its own. It plugs into a coding
              agent like Claude Code with custom commands that guide developer and tester agents
              as they build your feature, test it, and fix any issues. When the feature is ready,
              it can even ship it to your repo.
            

            

              The terminal below replays a real Frisson run, condensed. "Run again" moves on to three made-up examples.
            

            
            

              

                ~/frisson
                
              

              
> /shipyard "add an admin panel"
[plan]  3 tasks · 12 criteria
[build] dev agent → admin API ✓
[build] dev agent → dev admin login ✓
[build] dev agent → /admin panel ✓
[test]  tester agent → 828 tests ✓
[test]  browser agent → 99 steps ✓
[test]  12 of 12 criteria ✓
[ship]  branch shipped ↗
[pilot] /harbor → 19-step guide ✓

            

            

              What's the Harbor Pilot?
              

                
After a build, /harbor lays the real code out in the order the data moves, so a person can read it from start to finish.

                
It is not a reviewer: it does not approve, fix or score anything. You are the reviewer.

                
The code can't be paraphrased, because Claude only cites line ranges. A script copies those lines from the commit and refuses citations that don't exist.

                
/harbor ask answers with quoted lines. /harbor verify re-checks every snippet against the branch.
